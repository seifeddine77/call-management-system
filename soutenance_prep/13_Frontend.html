Architecture & Implémentation Frontend

Guide technique complet de l'interface client de la plateforme AutoAssist

1. Vue d'ensemble technologique

Le frontend d'AutoAssist est une application monopage (SPA) conçue pour offrir une expérience utilisateur fluide, rapide et visuellement premium aux opérateurs et superviseurs d'assurance.

React 19.2 TypeScript 5.9 Vite 8.0 Tailwind CSS 3.4 Framer Motion 12.0 Recharts 3.8

La réactivité et l'esthétique soignée (Aurora Design System) ont été les priorités de cette implémentation, s'appuyant sur des bibliothèques d'animations puissantes, du rendu SVG dynamique et des protocoles de communication temps réel.

3. Analyse approfondie des composants et pages clés

Chaque vue principale de l'application répond à une spécification stricte du cahier des charges opérationnel.

🔑 Écran de Connexion (LoginPage)
Fournit une entrée sécurisée validée par Zod. Intègre des canvas de particules animés à 60fps basés sur Vanta.js pour une esthétique unique.
📊 Tableau Kanban (QueuePage)
Permet la distribution interactive des dossiers sinistres entre les étapes. Géré via la bibliothèque de Drag-and-Drop native @dnd-kit.
📞 Détail du Ticket (TicketDetailPage)
Le cœur opérationnel. Intègre un player audio customisé avec extraction de forme d'onde, la dictée vocale temps réel avec Whisper et la validation de formulaires dynamiques.
⚙️ Moteur de Règles (RulesPage)
Éditeur visuel de conditions imbriquées (AND/OR). Rendu graphique interactif SVG complet représentant le processus d'évaluation des règles en temps réel.

Le cas de RulesPage (Simulation SVG & Animations)

Pour offrir une transparence totale aux superviseurs, la page de configuration des règles dessine l'évaluation des conditions sous la forme d'un arbre d'exécution. L'application calcule et trace des courbes de Bézier dynamiques :

const getBezierPath = (x1, y1, x2, y2) => { const dx = Math.abs(x2 - x1) * 0.5; return `M ${x1} ${y1} C ${x1 + dx} ${y1}, ${x2 - dx} ${y2}, ${x2} ${y2}`; };

Lorsque l'opérateur teste une règle avec des valeurs de simulation, le frontend résout les conditions et applique une animation de points pointillés lumineux sur les arcs valides (via `stroke-dashoffset` en CSS), permettant au superviseur de comprendre immédiatement pourquoi un dossier a été accepté ou refusé.

4. Moteur de Design "Aurora"

L'identité visuelle d'AutoAssist repose sur l'Aurora Design System, défini de manière centralisée dans index.css.

🎨 Concept d'implémentation
Plutôt que d'écrire des dizaines de classes alternatives avec le préfixe Tailwind dark:, nous utilisons des variables CSS sémantiques. Le mode sombre applique des teintes sombres ultra-profondes (Linear, Raycast) et le mode clair bascule sur des ombres épurées (Cal.com, Vercel).

Les dégradés de fond animés driftent lentement grâce au GPU :

/* index.css */ .mesh-bg::before { content: ''; position: fixed; background: var(--gradient-mesh); animation: meshDrift 25s ease-in-out infinite; }

5. Sécurité, Intercepteurs & Refresh Loop

La communication avec l'API Gateway (/api) est sécurisée à l'aide de jetons d'accès courts (JWT) et d'un jeton de rafraîchissement (Refresh Token) persistant.

// Intercepteur Axios - src/services/api.ts api.interceptors.response.use( (response) => response, async (error) => { const originalRequest = error.config; if (error.response?.status === 401 && !originalRequest._retry) { originalRequest._retry = true; try { const stored = localStorage.getItem('aurora-auth'); if (stored) { const { refreshToken } = JSON.parse(stored); const { data } = await axios.post(`${GATEWAY_URL}/api/auth/refresh`, { refreshToken }); localStorage.setItem('aurora-auth', JSON.stringify(data)); originalRequest.headers.Authorization = `Bearer ${data.accessToken}`; return api(originalRequest); // Rejeu de la requête en échec } } catch { localStorage.removeItem('aurora-auth'); globalThis.location.href = '/login'; } } throw error; } );

6. Dictée Vocale STT en Temps Réel (WebSocket)

Dans TicketDetailPage.tsx, l'opérateur peut transcrire sa conversation téléphonique en direct :

  • Enregistrement par tranches : Instanciation d'un MediaRecorder natif avec le codec audio/webm;codecs=opus.
  • Fréquence de découpage : Déclenchement automatique de la capture toutes les 3 secondes : recorder.start(3000).
  • Transmission asynchrone : Envoi immédiat des paquets binaires via un canal WebSocket vers le serveur IA.
  • Affichage dynamique : Réception des événements JSON de type partial ou final de Whisper et mise à jour de l'interface utilisateur.

7. Player Audio Customisé & Forme d'onde

Pour visualiser les appels passés, l'application implémente un analyseur audio haute fidélité :

🔊 Web Audio API
L'audio est récupéré de manière sécurisée sous forme de blob HTTP avec le token JWT. Ce blob est ensuite décodé dans un buffer à l'aide d'un AudioContext pour extraire les canaux PCM Float32 afin de générer la forme d'onde cliquable.
const arrayBuffer = await blob.arrayBuffer(); const audioContext = new AudioContext(); const audioBuffer = await audioContext.decodeAudioData(arrayBuffer); const channelData = audioBuffer.getChannelData(0); // PCM brut

8. Préparation de la Soutenance (Questions/Réponses)

Question classique du jury Argumentaire de défense
Pourquoi React et pas Angular ou Vue ? L'écosystème React 19 et Vite offre le meilleur rapport poids/performance. Le modèle de rechargement HMR de Vite a accéléré le développement et les bibliothèques d'animations comme Framer Motion ont permis de respecter le design premium exigé.
Comment sécurisez-vous le stockage local (localStorage) ? Le localStorage ne contient que le jeton JWT d'accès court. Si l'utilisateur le modifie, la Gateway rejette immédiatement l'appel. Les informations hautement sensibles ne sont jamais exposées côté client.
Comment gérez-vous la latence du modèle Whisper ? Whisper s'exécute localement sur notre conteneur IA optimisé. Le découpage de l'audio en tranches de 3 secondes permet d'éviter l'attente de la fin de l'enregistrement et de transcrire au fil de l'eau.
