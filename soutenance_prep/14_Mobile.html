Architecture Mobile (Flutter / Dart)

Guide technique complet de l'application mobile de terrain AutoAssist

1. Vue d'ensemble technologique

L'application mobile AutoAssist est développée à l'aide de Flutter, permettant aux experts et opérateurs de terrain de gérer les tickets, capturer des images et consulter le moteur de décision directement en mobilité.

Flutter SDK ^3.5.0 Dart 3.5 Provider 6.1 Secure Storage 10.0 Dio 5.9 FL Chart 0.69

La stack mobile met l'accent sur la sécurité matérielle, la persistance des performances graphiques locales et l'unification des services réseau avec notre Gateway centrale.

2. Structure du projet mobile

Le répertoire mobile suit une architecture Flutter propre organisée dans le dossier lib/ :

mobile/
├── android/ // Configuration Gradle & manifestes natifs
├── ios/ // Configuration native Xcode & clés Info.plist
├── lib/
│ ├── config/ // Colors.dart (Thèmes), Theme.dart (ThemeData)
│ ├── models/ // Mapping JSON strict en classes Dart (User, Ticket...)
│ ├── providers/ // AuthProvider.dart, ThemeProvider.dart (ChangeNotifier)
│ ├── screens/ // LoginScreen, TicketDetailScreen, DashboardScreen...
│ ├── services/ // ApiClient.dart (Dio), auth_service.dart, ticket_service.dart...
│ ├── shell/ // AppShell.dart (IndexedStack + BottomBar)
│ ├── main.dart // WidgetsFlutterBinding & runApp()
└── pubspec.yaml // Fichier de configuration npm-like pour les dépendances Flutter

3. Sécurité matérielle des Tokens

Contrairement au localStorage du Web qui stocke en clair, l'application mobile utilise FlutterSecureStorage :

🍎 iOS Keychain
Sous iOS, les clés JWT sont chiffrées et encapsulées au niveau du Keychain matériel, géré directement par le processeur d'Apple.
🤖 Android Keystore
Sous Android, les jetons sont chiffrés avec l'algorithme AES-256 et sauvegardés de façon protégée via l'API Android Keystore.

4. Client HTTP Dio & Intercepteur de Rafraîchissement JWT

Le fichier ApiClient centralise la connexion et implémente un intercepteur pour rafraîchir le jeton expiré (401) de façon transparente :

// extrait de services/api_client.dart onError: (error, handler) async { if (error.response?.statusCode == 401 && !_isRefreshing) { _isRefreshing = true; try { final refreshToken = await _storage.read(key: _refreshKey); if (refreshToken != null) { // Appel de rafraîchissement avec une instance Dio propre final res = await refreshDio.post('/api/auth/refresh', data: {'refreshToken': refreshToken}); final newToken = res.data['accessToken']; await _storage.write(key: _tokenKey, value: newToken); // Rejouer la requête d'origine en remplaçant le Header final opts = error.requestOptions; opts.headers['Authorization'] = 'Bearer $newToken'; final retryResponse = await retryDio.request(opts.path, options: Options(method: opts.method, headers: opts.headers)); return handler.resolve(retryResponse); } } catch (e) { await clearTokens(); } _isRefreshing = false; } return handler.next(error); }

5. Thèmes personnalisés et ThemeExtension

Pour unifier le Design System entre le web et le mobile, nous étendons les capacités de Flutter à l'aide de ThemeExtension.

🎨 ThemeExtension & Context extension
Grâce aux ThemeExtensions Dart, la classe AppColorScheme définit les palettes dark et light de manière centralisée. Un getter sur le BuildContext permet d'appeler les couleurs simplement : context.colors.surface.
// lib/config/colors.dart extension AppColorsX on BuildContext { AppColorScheme get colors => Theme.of(this).extension<AppColorScheme>()!; } // Rendu dans n'importe quel widget Widget build(BuildContext context) { final c = context.colors; return Container( color: c.surface, child: Text('Texte Aurora', style: TextStyle(color: c.text)), ); }

6. Système de Navigation avec IndexedStack

L'onglet de navigation principal utilise un composant structurel `IndexedStack` :

  • Rôle : Il charge les 4 écrans fondamentaux (Dashboard, Tickets, Queue, More) en mémoire.
  • Maintien d'état : Contrairement à un routage classique qui détruit et recrée la page, `IndexedStack` préserve la position de scroll et les filtres de saisie lorsque l'opérateur change d'onglet.
  • Animation : Géré de façon fluide en écoutant l'état local dans `app_shell.dart`.

7. Soutenance de Mobile (Questions/Réponses)

Question du jury Défense Technique
Pourquoi Flutter plutôt que React Native ? Flutter compile en code binaire ARM natif sans pont JS, ce qui garantit du 60/120 FPS constant. Le moteur graphique Impeller/Skia dessine chaque pixel lui-même, nous garantissant que le design Aurora est rigoureusement identique sur iOS et Android.
Quelle est la différence de sécurité avec le Web ? Sur le Web, le localStorage stocke les tokens en clair. Sur mobile, nous utilisons la Keychain iOS et le Keystore Android, qui sont des partitions sécurisées et chiffrées par le processeur physique.
Comment gérez-vous l'état de l'application ? Nous utilisons la bibliothèque Provider avec des ChangeNotifier. C'est le design pattern officiel recommandé par Google, qui offre une séparation propre (MVVM) et évite le surpoids de bibliothèques lourdes comme Redux ou BLoC.
